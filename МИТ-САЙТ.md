## LP-024 — Internal Pinterest Automation preview

Дата: 2026-09-01

### Решение

- На LayerPorter добавляется изолированный внутренний маршрут:
  `/internal/pinterest-automation/`.
- Источник интерфейса: `OlegStrateg/Pinterest-Automation`, ветка `feat/01-interface-prototype`, кандидат v0.0.1.
- Маршрут не добавляется в меню, sitemap или `llms.txt`.
- Для маршрута обязательны:
  - `meta robots=noindex,nofollow,noarchive,nosnippet,noimageindex`;
  - `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet, noimageindex`;
  - `Cache-Control: private, no-store`.
- `robots.txt Disallow` намеренно не используется: поисковый робот должен иметь возможность прочитать `noindex`.
- Live Pinterest publishing остаётся выключенным.
- Добавлен первый реальный серверный контур: `/internal/pinterest-automation/health`.
- Health endpoint возвращает только безопасные состояния: доступность preview API, наличие/отсутствие Pinterest App ID/Secret, режим preview и принудительный `livePublishing:false`. Значения секретов наружу не возвращаются.
- Интерфейс запрашивает health endpoint и показывает фактический статус Preview API.
- Production workflow обязан проверять HTML noindex, HTTP X-Robots-Tag, assets, health JSON и отсутствие внутреннего URL в sitemap.

### Recovery

Перед изменением создана ветка:
`recovery/pre-pinterest-automation-preview-2026-09-01`
от commit `e44aeda188e99018d63a68e0a47a7a69c6dd4c2c`.

Дата: 2026-09-01

### Цель

`List Pins → Get Pin?pin_metrics=true → Pin ID → Board ID → metrics signal`.

### Проверка источников

Официальный Pinterest Sandbox поддерживает:
- List Pins;
- Create Pin;
- Get Pin;
- boards CRUD.

Отдельные organic analytics endpoints в списке Sandbox-supported endpoints не указаны.

Поэтому в Sandbox:
- обязательный PASS — List Pins + Get Pin + совпадение Pin ID + наличие Board ID;
- `pin_metrics=true` запрашивается как официальный summary signal;
- отсутствие `pin_metrics` не считается провалом Sandbox-цикла;
- dedicated organic analytics проверяется после Trial/Production.

1. После `POST /v5/pins` сервер сам делает `GET /v5/pins/{pin_id}?pin_metrics=true`.
2. Readback имеет bounded retry только для transient состояний:
   - network error;
   - 404 сразу после создания;
   - 429;
   - 5xx.
3. Результат сохраняется в account state:
   - `last_pin_id`;
   - `last_pin_created_at`;
   - `last_pin_verified`;
   - `last_pin_metrics_available`;
   - `last_pin_checked_at`.
4. Добавлен read-only diagnostics endpoint:
   `GET /internal/pinterest-automation/api/diagnostics?account_id=...`
5. Diagnostics всегда делает реальный `List Pins`, затем `Get Pin`.
6. Если ранее сохранённый Pin найден в списке — проверяется он; иначе берётся самый свежий Pin по `created_at`.
7. UI показывает:
   - List Pins;
   - Get Pin;
   - Pin ID match;
   - Board ID;
   - Pin metrics available / not returned;
   - фактический Pin ID;
   - время проверки.

### Безопасность

- endpoint требует admin session;
- Production Live остаётся `false`;
- токены не возвращаются и не логируются;
- diagnostics ничего не публикует;

## LP-039 — Точные SEO-вхождения Home по утверждённой семантике

Дата: 2026-09-02

Статус: CANDIDATE

### Причина

После LP-038 выявлено системное несоответствие: в нескольких локалях утверждённый SEO-root находился в title, но отсутствовал в meta description, а secondary-фразы из meta description отсутствовали в видимом полном тексте или использовались в другой неподтверждённой форме.

Примеры до исправления:
- RU: title «расширения для браузера», но root отсутствовал в description;
- ES: утверждено «extensiones de Chrome», использовалось «Extensiones para Chrome»;
- DE: утверждено «Chrome-Erweiterungen», использовалось «Browser-Erweiterungen für Chrome»;
- JA: утверждено «Chrome 拡張機能», использовалось «Chrome拡張機能».

- EN проверен и изменений не потребовал;
- RU / DE / ES / FR / PT-BR / JA / ZH-CN: meta description синхронизирован с утверждёнными root/secondary;
- те же SEO-фразы добавлены естественным точным вхождением в видимый полный текст;
- og:description и twitter:description синхронизированы с основным meta description;
- title не менялись;

### Новое обязательное правило

- утверждённый root из title должен присутствовать в description и body;
- значимые SEO-фразы из description должны присутствовать в body;

- редакторская вычитка не может уничтожать утверждённое exact-вхождение;

### Зафиксированное решение

LayerPorter развивается как единая Growth OS с четырьмя связанными контурами:

1. SEO / Web Tools — органический вход и мгновенная бесплатная ценность.

- Search architecture != Navigation architecture.
- Один самостоятельный поисковый intent получает одного URL owner.

- Массовая локализация без спроса и quality gate запрещена.
- Одна capability по возможности обслуживает Web / SEO / Extension / MCP / future API.
- Новые функции ранжируются через Opportunity Score.
- Каждый tool проходит Tool Quality Gate.
- Существенные решения проходят независимый review всех профильных ролей и Red Team.
- Финальное стратегическое решение собирает главный стратег после разрешения конфликтов, а не голосования специалистов.
