## LP-024 — Internal Pinterest Automation preview

Дата: 2026-09-01

### Решение

- На LayerPorter добавляется изолированный внутренний маршрут:
  `/internal/pinterest-automation/`.
- Источник интерфейса: `OlegStrateg/Pinterest-Automation`, ветка `feat/01-interface-prototype`, кандидат v0.0.1.
- Маршрут не добавляется в меню, sitemap или `llms.txt`.
- Для маршрута обязательны:
  - `meta robots=noindex,nofollow,noarchive,nosnippet,noimageindex`;
  - `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet, noimageindex`;
  - `Cache-Control: private, no-store`.
- `robots.txt Disallow` намеренно не используется: поисковый робот должен иметь возможность прочитать `noindex`.
- Live Pinterest publishing остаётся выключенным.
- Добавлен первый реальный серверный контур: `/internal/pinterest-automation/health`.
- Health endpoint возвращает только безопасные состояния: доступность preview API, наличие/отсутствие Pinterest App ID/Secret, режим preview и принудительный `livePublishing:false`. Значения секретов наружу не возвращаются.
- Интерфейс запрашивает health endpoint и показывает фактический статус Preview API.
- Production workflow обязан проверять HTML noindex, HTTP X-Robots-Tag, assets, health JSON и отсутствие внутреннего URL в sitemap.

### Recovery

Перед изменением создана ветка:
`recovery/pre-pinterest-automation-preview-2026-09-01`
от commit `e44aeda188e99018d63a68e0a47a7a69c6dd4c2c`.

### Архитектурное решение

- Используется официальный Pinterest Sandbox API: `https://api-sandbox.pinterest.com/v5`.
- Production OAuth и production `pins:write` пока не включаются.
- Канонический код gateway хранится в `OlegStrateg/Pinterest-Automation`, ветка `feat/02-sandbox-live-contour`.
- LayerPorter содержит только deployment copy для живого preview.
- Вводится внутренний пароль `PINTEREST_PREVIEW_PASSWORD`; без него API записи недоступен.
- Sandbox token хранится только в Cloudflare secret `PINTEREST_SANDBOX_TOKEN`.
- Ни пароль, ни токен не коммитятся и не возвращаются API.
- Auth cookie: HttpOnly + Secure + SameSite=Lax, срок 7 дней.
- `POST /api/pins` требует явное `confirm=CREATE_SANDBOX_PIN`.
- После создания Pin интерфейс сразу выполняет обратное чтение Pin по `pin_id`.
- Production `livePublishing` остаётся `false`.

### Endpoint'ы

- `GET /internal/pinterest-automation/health`
- `GET /internal/pinterest-automation/auth/status`
- `POST /internal/pinterest-automation/auth/login`
- `POST /internal/pinterest-automation/auth/logout`
- `GET /internal/pinterest-automation/api/boards`
- `POST /internal/pinterest-automation/api/pins`
- `GET /internal/pinterest-automation/api/pin?pin_id=...`

## LP-027 — Управление Pinterest-аккаунтами из админки

Дата: 2026-09-01

### Цель

Убрать ручное управление токенами через Cloudflare и сделать штатный продуктовый сценарий подключения аккаунтов из внутренней панели.

### Решение

- В настройках Pinterest Automation добавляется раздел «Аккаунты Pinterest».
- Sandbox-аккаунт подключается через:
  `+ Подключить аккаунт → Sandbox → Access Token → Проверить и подключить`.
- Перед сохранением токен проверяется официальным Pinterest Sandbox API:
  - `GET /v5/user_account`;
  - `GET /v5/boards`.
- После успешной проверки сохраняются:
  - внутренний `account_id`;
  - label;
  - username;
  - тип аккаунта;
  - среда;
  - токен;
  - количество досок;
  - время подключения/проверки.
- В UI токен после подключения отображается только маской и последними 4 символами.
- Для каждого API-запроса требуется явный `account_id`; токены разных аккаунтов не смешиваются.
- Production остаётся выключенным; ручной production token не вводится. После одобрения Trial production-подключение будет только через OAuth Authorization Code.

### Хранилище

На текущем этапе используется существующий Cloudflare KV binding `FEEDBACK_KV` с отдельным префиксом `pa:`.

Cloudflare KV автоматически шифрует значения at rest. Токены:
- не попадают в Git;
- не возвращаются API целиком;
- не пишутся в логи;
- удаляются из KV при отключении аккаунта.

Отдельный KV namespace для Pinterest можно вынести позже, если потребуется инфраструктурное разделение; для текущего MVP это не блокер.

### Доступ

- Отдельная admin session хранится в KV.
- Cookie: HttpOnly + Secure + SameSite=Lax.
- Сессия живёт 7 дней.
- Write-запросы дополнительно проверяют same-origin.
- Неавторизованный доступ к `/admin/accounts`, boards и pins запрещён.

### Endpoint'ы

- `GET/POST/DELETE /internal/pinterest-automation/admin/auth`
- `GET/POST/DELETE /internal/pinterest-automation/admin/accounts`
- `GET /internal/pinterest-automation/api/boards?account_id=...`
- `POST /internal/pinterest-automation/api/pins` с `account_id`
- `GET /internal/pinterest-automation/api/pin?account_id=...&pin_id=...`

## LP-028 — Новый Sandbox-аккаунт без досок

Дата: 2026-09-01

### Проблема

После подключения нового Pinterest Sandbox account тест Pin останавливался, если `GET /v5/boards` возвращал пустой список.

Это штатный случай: Sandbox boards/Pins отделены от production, поэтому новый Sandbox account может иметь 0 досок.

### Решение

- `POST /internal/pinterest-automation/api/boards` создаёт Sandbox board через официальный `POST /v5/boards`.
- Создание требует:
  - авторизованную admin session;
  - same-origin write;
  - явное `confirm=CREATE_SANDBOX_BOARD`;
  - явный `account_id`;
  - Sandbox environment.
- Если при тесте Pin список досок пуст:
  1. UI предлагает создать `LayerPorter Sandbox Test`;
  2. после подтверждения создаёт доску;
  3. обновляет список boards;
  4. продолжает тест Pin без повторного подключения аккаунта.
- При ошибке чтения boards автоматическое создание не запускается.
- После создания обновляется `board_count` аккаунта.
- Production Live остаётся выключенным.

### Проверка по документации

Pinterest Sandbox поддерживает:
- List boards;
- Create board;
- Create Pin;
- Get Pin.

Payload тестовой доски:
- name: `LayerPorter Sandbox Test`;
- description: техническое описание;
- privacy: `PUBLIC`.
