# ADR-001 — SEO-страницы инструментов + единый LayerPorter Workspace

Дата: 2026-09-01  
Статус: ПРИНЯТО  
Issue: #97

## Решение

LayerPorter разделяет поисковый слой и рабочую среду.

### 1. Каждый поисковый интент получает отдельную SEO-страницу

Примеры:

- /ru/tools/obrezat-foto/
- /ru/tools/izmenit-razmer-foto/
- /ru/tools/udalit-fon/
- /ru/tools/sdelat-mem/
- /en/tools/crop-image/
- /en/tools/resize-image/
- /en/tools/remove-background/
- /en/tools/meme-maker/

Каждая страница имеет собственные:

- URL;
- title;
- meta description;
- H1;
- локальную семантику;
- контент;
- FAQ при необходимости;
- internal links;
- canonical;
- hreflang;
- поисковый intent.

Один и тот же функциональный модуль может обслуживать множество языковых и семантических SEO-страниц.

### 2. Первое действие находится прямо на SEO-странице

Страница не должна быть рекламной прокладкой перед инструментом.

На первом экране пользователь сразу получает основное действие:

- загрузить файл;
- перетащить файл;
- выбрать изображение;
- начать обработку.

SEO-текст не должен блокировать первый полезный сценарий.

### 3. После первого действия открывается единый Workspace

После загрузки файла или начала обработки пользователь попадает в полноэкранный LayerPorter Workspace.

Workspace — единая профессиональная рабочая среда без SEO-контента в рабочем поле.

Базовая модель:

- слева — инструменты;
- по центру — рабочее поле / canvas;
- справа — настройки;
- отдельные режимы для изображения и видео;
- общий экспорт;
- общее состояние;
- undo/redo;
- лениво подключаемые модули.

### 4. SEO-URL и внутренние режимы Workspace не обязаны совпадать

После входа в Workspace пользователь может переключаться:

Crop → Resize → Text → Meme → Remove Background

без обязательной смены SEO-URL на каждом действии.

SEO-страницы отвечают за привлечение поискового трафика.
Workspace отвечает за выполнение работы и дальнейшее редактирование.

Не строить SEO на искусственной подмене URL через pushState.

### 5. Расширения используют тот же Workspace

Chrome / Яндекс Браузер расширения не обязаны проходить через SEO-посадочную.

Пример:

Pinterest Downloader → Edit → Workspace в нужном режиме

Picture Converter → Edit → Workspace в нужном режиме

Будущие расширения → действие → тот же Workspace.

### 6. Общее ядро должно быть модульным

Общее ядро не означает один тяжёлый JS-bundle.

Целевая структура:

Workspace Shell
- общий UI;
- состояние;
- импорт;
- экспорт;
- undo/redo;
- routing продукта;

Image Runtime
- crop;
- resize;
- rotate;
- text;
- meme;
- layers;

Video Runtime
- trim;
- crop;
- resize;
- timeline;

AI-модули
- background removal;
- object removal;
- OCR;
- другие тяжёлые функции.

Тяжёлые части загружаются только по фактическому действию пользователя.

## Почему выбрана эта модель

Проверена практика:

- iLoveIMG;
- Img2Go;
- Adobe Express;
- Canva;
- Convertio;
- CloudConvert;
- FreeConvert;
- Online-Convert.

Общий повторяющийся паттерн рынка:

1. отдельный SEO-вход под конкретный intent;
2. полезное действие сразу на странице;
3. общее технологическое ядро;
4. у более сильных продуктовых систем — переход в широкую рабочую среду после первого действия.

Для LayerPorter эта модель дополнительно усиливается собственными браузерными расширениями как отдельным каналом входа в тот же Workspace.

## Что отклонено

### Вариант A — один SPA и множество виртуальных SEO-URL

Отклонён.

Причины:

- слабее для Google/Яндекса;
- сложнее рендеринг и индексация;
- повышенный риск ошибок canonical/history;
- SEO становится зависимым от клиентского JavaScript.

### Вариант B — отдельный редактор на каждой SEO-странице

Отклонён.

Причины:

- дублирование кода;
- сложное развитие;
- разные состояния и UX;
- высокий технический долг.

### Вариант C — SEO-страница только как текстовая прокладка к /editor/

Отклонён.

Причины:

- лишний шаг;
- хуже конверсия;
- пользователь не получает действие сразу;
- слабее соответствие инструментальному поисковому intent.

## Проверки перед реализацией

Минимум три независимых проверки:

1. SEO: индексируемость, intent, canonical, hreflang, отсутствие каннибализации.
2. UX/CRO: первое полезное действие без лишнего шага, сохранение файла при переходе в Workspace.
3. Техническая: производительность, ленивые модули, сохранение состояния, отсутствие лишней загрузки тяжёлых движков.

## Ограничения

- не создавать SEO-страницу без подтверждённого самостоятельного intent;
- не создавать несколько URL под синонимы одного и того же intent без реальной поисковой причины;
- не загружать видео/ИИ-движки на страницах, где они не нужны;
- не превращать Workspace в SEO-страницу;
- не дублировать редактор по расширениям;
- не менять эту архитектуру без отдельного ADR.
