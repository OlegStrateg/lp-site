# LP-123 — ИИ-редактирование на странице Resize Image
Дата: 13 октября 2026. Статус: CANDIDATE, НЕ ВКЛЮЧЕНО И НЕ ПРОВЕРЕНО НА PRODUCTION.
Git baseline: 95d9351cf3ebc2c441abb41b00ff707c645e9c5d (`OlegStrateg/lp-site`, ветка `master`).
Решение: отдельная опциональная панель ИИ ниже текущего Resize; оба языка EN/RU; существующий браузерный resize не меняется по логике. API — Cloudflare Pages Function.

## Куда вставить ключ и что нужно включить
Cloudflare → Workers & Pages → layerporter → Settings → Variables and Secrets → Add → Encrypt.
Секреты: `AI_IMAGE_API_KEY` (API-провайдер), `AI_IMAGE_EDIT_URL` (полный HTTPS адрес OpenAI-совместимого multipart edits endpoint), `AI_IMAGE_MODEL` (точный model ID), `AI_IMAGE_OWNER_PASSWORD` (уникальный пароль >=24 символов), `AI_IMAGE_QUOTA_SALT` (случайная строка >=24 символов), `AI_IMAGE_TURNSTILE_SECRET` (Turnstile secret).
Переменная, не секрет: `AI_IMAGE_TURNSTILE_SITE_KEY` (public site key).
Отдельно Cloudflare D1 → создать БД `layerporter-ai-limits`; выполнить `scripts/sql/ai-image-quotas.sql`; добавить D1 binding `AI_IMAGE_DB` к Cloudflare Pages project для production и preview.
Без всех перечисленных значений сервер отвечает 503 и платные вызовы невозможны. Значения не коммитить в Git.
Важное: сам API-провайдер пока НЕ УСТАНОВЛЕН. Нужно проверить, что он принимает стандартные multipart поля image,prompt,model,n,output_format и возвращает data[0].b64_json. До публикации обновить Privacy Policy, указав точное юрлицо провайдера и его политику хранения данных. Установить денежный бюджет у провайдера.

## Лимиты и безопасность
Для публики 1 запрос на IP-адрес в день, суммарно 20 платных запросов на UTC день по всему сайту; строгое резервирование места до вызова провайдера одним атомарным оператором SQL в D1. Неиспользование KV исключает гонки из-за eventually consistent хранения.
Владелец: отдельный ввод длинного пароля → cookie HttpOnly Secure 24 часа, обход квот только на сервере. Публичные запросы требуют server-side Turnstile. На изображение не более 6 МиБ; JPEG/PNG/WebP + проверка сигнатуры; текст до 800 символов.
Не сохранять изображения и запросы в аналитике. При неизвестном статусе биллинга после таймаута зарезервированная квота остаётся потраченной — защита расходов важнее повтора.

## Три проверки
1. Безопасность: прямые POST без Origin или Turnstile, неверный пароль, поддельный cookie, отсутствие D1 или ключа, параллельные запросы и пределы бюджета.
2. Функционал: загрузить JPG/PNG/WebP; resize прежний; обработка по запросу; до/после; скачать; повторно редактировать; переключение языков и 390px.
3. Production: GitHub CI, отдельная preview-сборка, реальная генерация с ключом, мониторинг расходов, корректность disclosure, smoke после production.
Всё ещё требуется настройка Cloudflare и фактическое тестирование с API, до них НЕ публиковать.

## 18 октября 2026 — концепция текстового редактора и реализация кандидата

Ключевое изменение: не Photoshop и не инструменты поверх Canvas. Главный путь: фото → текстовая правка → результат → уточнение следующим текстом. Отдельные инструменты Crop/Resize сохранены.

Готово в рабочей ветке:
- Диалоговый сценарий с контекстом до 6 последних принятых правок по выбранной цепочке.
- Версионное дерево: исходник + последующие версии; выбор любого старого результата и создание новой ветки. Хранение в памяти браузера, без сервера и без сохранения после перезагрузки страницы.
- Необязательная точка на фото; в запрос передаётся процентная позиция с уточнением, что это НЕ маска, точность границы не гарантируется.
- Сравнение исходной и текущей версии, скачивание, передача в прежний Resize / Crop.
- Опциональный второй референс: оригинальное фото в multipart через image[] (текущая версия первой, оригинал вторым) для сохранения индивидуальности.
- APIMaster и совместимые провайдеры: синхронный /images/edits; ответ b64_json или HTTPS URL с ограниченным списком доверенных доменов. Для ссылок обязательна серверная проверка MIME и размера.
- Публичный лимит изменён на 3 запроса/IP/сутки, общий дневной лимит 20; владелец освобождён от квоты посетителя, но лимит расходов провайдера обязателен.
- Большие картинки уменьшаются только при отправке в API: исходники и результаты остаются в памяти в первоначальном качестве.

ДОПОЛНИТЕЛЬНО для APIMaster: если маршрут возвращает временные URL изображений, заполнить `AI_IMAGE_RESULT_HOSTS` — точные хосты, разделённые запятыми, например домены CDN, выясненные из тестового ответа. Без allowlist URL-результат НЕ обрабатывается. Нельзя добавлять произвольные/недоверенные хосты.

Зависимости: новых пакетов нет, исключительно нативные браузерные API. Поиск GitHub: markfulton/NanoBananaEditor (AGPL-3.0; нельзя просто копировать), warpdotdev-demos/nano-banana-editor (лицензия не подтверждена), james-tn/gpt-image-editor (MIT), replicate/kontext-chat (лицензия не подтверждена). Использована методика, исходные реализации не копируются.

Тесты: единичные проверки prompt/context/point/url/квот и заглушка ответа провайдера, статическая сборка, регрессия существующих инструментов. Превью и реальный API **всё ещё не проверены**.

Ограничения и недоделки: нет точной маски выделения; нет обещания сохранения лица; изображение хранится в памяти текущей страницы; при неопределённом списании денег повтор не производится автоматически; политика конфиденциальности должна раскрыть фактического API-провайдера; требуется внешний денежный бюджет; не мержить до живой проверки.

## Исправление архитектуры — 18 октября 2026
Причина: встроенный блок под Resize противоречил основному сценарию и не имел собственной загрузки.
Решение: отдельные маршруты /tools/ai-image-editor/ и /ru/tools/ai-image-editor/, Resize/Crop возвращены к production master без изменений (регрессионная проверка).
Пользователь: загрузка JPG/PNG/WebP, перетаскивание и вставка из буфера, изображение слева, текстовый диалог справа, версии и сравнение, скачивание. Не зависит от Resize / его входного файла.
Максимум оригинала: 25 МБ, декодирование в браузере, площадь не более 80 млн пикселей; при отправке применяется прежнее сжатие до 6 МБ.
Публикация: только lp-123-ai-preview.layerporter.pages.dev; публичная генерация на Pages preview заблокирована до полного подключения провайдера, D1, Turnstile, бюджетного лимита и отдельного разрешения.
Проверки: (1) новая EN/RU страница и отсутствие AI в Resize, (2) работоспособность клиента и импорта через загрузчик, (3) API quotas и отсутствие платных preview-вызовов.
Статус: CANDIDATE, не REAL-API VERIFIED; основной сайт не менялся.

## 18 октября 2026 — референсы фотографий и понятная загрузка
Обнаруженный дефект: заголовок «Меняйте фото словами» не обозначал полноценный фоторедактор; пользователь не видел, как загрузить образцы лица, одежды и фона. Изначально можно было загрузить только основную фотографию.
Исправлено: явная кнопка загрузки исходной фотографии в верхней панели, русское название «ИИ-редактор изображений», блок прикрепления до 3 отдельных референсов у текстового поля.
Референсы имеют миниатюры и назначения: одежда, лицо, фон, предмет, стиль. Каждый можно удалить; замена основного фото сбрасывает референсы. Подтверждение и отправка только по явной команде.
Порядок multipart: текущая версия как изображение 1; оригинал (если есть) как изображение 2; дополнительные образцы далее. Все идут как image[] с ролями в запросе. Настройка server limits: <=3 образца, <=2 МиБ каждый после подготовки в браузере, общий объём изображений <=18 МиБ; 21 МиБ предохранитель content-length, отказ до платного запроса при некорректной схеме.
Изображения для референсов не являются гарантиями идентичности лица/материала: результат требует реального теста провайдера.
Критерии приёмки: 3 независимых проверки (сборка интерфейса EN/RU, контракт multipart с референсами/блокировкой лишних файлов, браузерная загрузка исходника и дополнительного фото). Не подтверждать VERIFIED до живого теста и реальных генераций.

## 18 октября 2026 — исправление неактивной кнопки
Причины: пустая команда и неактивный Preview API одновременно влияли на disabled, однако UI не различал их и прятал вход владельца внизу.
Решение: при пустой команде button disabled и явная подпись; при наличии исходной фотографии и непустой команды кнопка остаётся кликабельной даже при неготовом API и показывает причину отказа без сетевого платного вызова. Форма входа владельца находится рядом с CTA и показывается только если отдельный Preview конфиг готов; статус ownerLoginReady приходит как Boolean без раскрытия ключей.
Проверки: URL и референсы, GET API, отсутствие платного вызова без авторизации, UI EN/RU, GitHub CI. НЕ считать GPT VERIFIED без реального теста.

## 18 октября 2026 — запрет публикации недоступного ИИ-редактора (LP-123)
Ошибка первопричины: CI проверял только сборку HTML, наличие маршрутов и `available=false`; таким образом заведомо выключенный редактор считался «успешно опубликованным».
Установлен **релизный барьер до развёртывания**:
1. Непосредственная проверка конфигурации Cloudflare **Preview**, а не Production. Требуются зашифрованные `AI_IMAGE_API_KEY` и `AI_IMAGE_OWNER_PASSWORD`. Нельзя читать, отображать или сохранять их значения.
2. Проверка контрактов переменных и флагов по Wrangler.
3. Сборка и все проверки кода.
4. Сквозной Chromium: загрузка, референсы, текстовая команда, запрет анонимного вызова, фиктивная генерация, ветки версий, сравнение, сброс, мобильный и настольный экран.
5. После развёртывания обязательный `ownerLoginReady=true`, `available=false` для анонимного пользователя, проверка русской/английской страницы и неизменности Resize.
6. Сведения `ownerLoginReady` НЕ подтверждают доступность модели или баланс APIMaster. До отдельного фактического теста платного редактирования статус остаётся `CANDIDATE`.
7. Развёртывание запускается вручную, автоматическое обновление сайта из рабочих коммитов отключено.
При отсутствии секретов процесс останавливается **до** публикации, выдавая конкретные имена недостающих переменных и место настройки. Пользователю не предлагается повторять бессмысленные операции с неактивным редактором.

## 18 октября 2026 — честный статус модели и диагностируемые ошибки провайдера
- Наличие ключа и выполненный вход — только состояние CONFIGURED, а не VERIFIED.
- После успешного ответа с изображением UI показывает подтверждение ответа; фактическую проверку платного провайдера подтверждает только настоящий сетевой запрос, не подменённый Chromium.
- Коды ошибок от APIMaster разделены: авторизация (401/403), баланс (402), частотный лимит (429), неподдерживаемые параметры (400/404/422), неполадки upstream (5xx). Исходный текст ошибки провайдера, секреты и промпт не отражаются обратно клиенту.
- Автоматических повторных платных запросов нет.
