# Audit first — рекомендуемый вход в Website Image Optimizer

Дата: 2026-09-13.
Статус: **PRODUCT DECISION / NOT IMPLEMENTED**. Документ задаёт следующий продуктовый срез; не подтверждает наличие функции в production.
Репозиторий: OlegStrateg/layerporter-site. Реализацию вести от актуального master в отдельной ветке; документационная ветка не является базой для слепого переноса старого кода.

## Решение владельца и рекомендация

Первый рекомендуемый сценарий оптимизатора — **«Проверить страницу»**: аудит находит конкретные проблемы, объясняет последствия и показывает ценность исправления. Прямая оптимизация файла остаётся доступной.

Путь: URL → аудит → 3–5 приоритетных проблем → подготовка исправлений → сравнение → скачивание файлов / patch. Подробности раскрываются ниже, интерфейс не превращается в простыню SEO-текста.

V1 — комплексная проверка ОДНОЙ страницы в заявленных категориях. Нельзя называть её полным аудитом сайта. Статический HTML не даёт тех же наблюдений, что реальный браузер: непроверенные категории показываются отдельно.

## Что входит в первый аудит

| Категория | Что проверять | Граница выводов |
| --- | --- | --- |
| Изображения | Доступность, MIME, байты, размеры, кандидаты на другой формат/размер | Экономию подтверждать пробной обработкой, не угадывать процент |
| Разметка изображений | alt, декоративные изображения, img/src, srcset/sizes, width/height, loading | Пустой alt у декоративного изображения допустим; отсутствие любого атрибута не автоматически критическая ошибка |
| Контекст изображений | Соответствие описания видимому изображению и назначению на странице, окружение/подпись | Для смыслового alt нужен просмотр изображения; не выдумывать объекты и не набивать ключевые слова |
| Базовая SEO-разметка страницы | HTTP, title, description, H1, canonical, meta robots / X-Robots-Tag, доступность изображения для обхода | Отсутствие description не доказывает потерю позиций; noindex может быть намеренным |
| Производительность | Переданный вес изображений, размеры в браузере, загрузка первого экрана, доступные лабораторные измерения | Лабораторные и полевые данные разделять; один запуск не доказывает улучшение INP, CWV или конверсии |
| Метаданные | Существующие сведения об авторе/лицензии; применимость структурированных данных | Не придумывать права, автора и лицензию; не удалять существующие сведения вслепую |

Проверка rendered-размеров, динамических изображений и первого экрана требует браузерного наблюдения. Если его нет, отчёт честно ограничивается статическим HTML. При отсутствии CrUX/GSC показывать «нет данных», а не нули.

Не переименовывать уже индексируемые изображения автоматически ради ключевых слов: изменение URL требует обновления ссылок и отдельной оценки. Для новых файлов можно предлагать короткие описательные имена.

## Как выглядит полезная находка

Каждая карточка содержит:
- конкретную страницу, изображение или элемент;
- наблюдение и доказательство: значение атрибута, статус ответа, байты, скриншот или результат проверки;
- приоритет и понятную причину;
- вероятное последствие отдельно от измеренного результата;
- точное предлагаемое исправление;
- статус: можно подготовить автоматически / нужна проверка человеком / не проверено.

Не использовать вымышленные потери трафика, продаж или «SEO-баллы» без прозрачной методики. Общая статистика с источником может объяснять значимость проблемы, но не становится прогнозом для этой страницы.

Пример измеренной ценности из реального MCP-теста: fashion-reference-960.webp, 960×1329, 68 926 байт → WebP 62 342 байта (−9,55%) или AVIF 39 934 байта (−42,06%). Размеры сохранены, полученные ресурсы полностью декодированы. AVIF заметнее смягчает детали; меньший файл не автоматически лучший выбор. Эти числа не означают соответствующее ускорение всей страницы.

## Архитектура и результат исправления

Опубликованный @layerporter/image-optimizer-mcp@0.1.0 переиспользуется для детерминированной обработки изображений. Более широкий аудит координирует агент/skill с доступными HTML- и браузерными инструментами. Не объявлять дополнительные проверки возможностями уже выпущенной версии MCP.

Первый пилот — агентный сценарий на существующем MCP. Публичный веб-аудит произвольных URL потребует отдельного решения по исполнению, лимитам и защите сетевых запросов; не считать локальный stdio сервер готовым hosted API.

Выход зависит от входа:
- Только публичный URL: оптимизированные файлы, отчёт и рекомендации замены. Не обещать исходники чужого приложения.
- Предоставленные статический HTML и assets: изменённый комплект с проверкой ссылок и предпросмотром.
- Репозиторий Astro/другого приложения: изменения исходников и проверяемый diff, затем сборка и preview.

«Готово к деплою» допустимо только после проверки подходящего проекта/комплекта. Автоматический deploy не входит в этот срез. Временные process-local resource URI нужно прочитать и материализовать до окончания процесса; они не являются постоянными ссылками скачивания.

## Приёмка первого среза

На одной реальной странице LayerPorter:
1. Получить аудит с проверяемыми находками и явными границами покрытия; не менять страницу во время диагностики.
2. Подготовить исправление хотя бы одной подтверждённой проблемы изображения и, если обнаружена, одной проблемы разметки. Не создавать искусственную проблему ради теста.
3. Получить реальные файлы через MCP Resources, проверить MIME/размеры/полный decode, показать до/после и изменение байтов.
4. Для patch — проверить ссылки, сборку и отображение изменённой страницы, не потерять смысл alt и существующие сведения о правах.
5. Сохранить доказательства, ограничения и перечень оставшихся ручных действий. Не считать доступность страницы или зелёную сборку доказательством работы всего сценария.

Метрики: завершённый аудит → подготовленное исправление → полученный файл/patch. Улучшение веса измеряется отдельно от скорости, поискового трафика и установок расширения.

## Передача исполнителю

Рекомендуемый исполнитель: существующий чат разработки по подписке, умеющий работать с репозиторием и браузером. Владелец передаёт задание вручную.

Задание: прочитать этот документ и инструкции репозитория; проверить актуальный master и существующие возможности; на отдельной ветке feat/image-audit-first реализовать минимальный агентный пилот «URL → доказанный аудит → исправления изображений и разметки → файлы/patch → preview». Переиспользовать перечисленные экспертные материалы после проверки лицензий и фиксации версий; не писать новый общий SEO-фреймворк и не запускать массовый веер агентов. Стоп после одного проверенного пользовательского пути. В отчёте дать SHA, diff, команды/результаты smoke, реальные выходные файлы и ограничения. Не изменять опубликованную 0.1.0, не мержить, не публиковать и не деплоить.

Полный обход сайта, тепловые карты, 52 локали и общий сервис автодеплоя — последующие решения; не условия готовности первого среза.
