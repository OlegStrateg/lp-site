## 1. Продуктовое решение

Virtual Try-On является отдельным инструментом сайта LayerPorter, а не конвертером и не отдельным сайтом.

Канонический путь инструмента: `/tools/virtual-try-on/`.

`/convert/` не изменяется: он остаётся каталогом конвертеров.

Архитектура должна позволять повторно использовать ядро в будущем Chrome-расширении без создания второго движка.

## 2. Принцип реализации

Два уровня качества:

1. `Instant Preview` — бесплатная локальная обработка в браузере. Никакого нашего GPU/API на каждую примерку.
2. `HD Try-On` — отдельный будущий генеративный слой, вызываемый только по явному действию пользователя. Не входит в первый MVP до проверки коммерчески чистого модельного стека.

Первый MVP намеренно ограничен верхней одеждой: футболки, рубашки, свитеры, куртки и похожие вещи. Нельзя выдавать геометрический preview за точный прогноз размера, посадки или физики ткани.

## 3. Open Source First

### Основной инженерный референс

`pravoobi/try-on` / `@practics/tryon-core`:

- framework-free ядро;
- MIT;
- on-device;
- pose estimation;
- person segmentation;
- garment warp;
- compositing;
- WebGPU/LiteRT подход.

Код демонстрационного приложения не копируется вслепую. Используем архитектурные решения и отдельно проверяем каждый переносимый компонент и лицензию.

### MVP runtime

Для первой изолированной версии используется MediaPipe Tasks Vision в браузере для определения позы. Версия runtime закреплена на `@mediapipe/tasks-vision@1.0.1`, модель закреплена на `pose_landmarker_lite/float16/1`. Фото пользователя и вещи LayerPorter не отправляет на свой сервер.

MediaPipe может отправлять Google технические метрики производительности/использования; это явно сообщается пользователю до первого запуска.

### HD-контур

FASHN VTON 1.5 остаётся исследовательским кандидатом, но не включается в production, пока весь preprocessing/parser stack не очищен от некоммерческих зависимостей.

## 4. Три независимые проверки

### Проверка A — функциональная

`фото человека + фото вещи -> pose -> локальный composite -> результат -> скачать PNG`.

Проходят также повторная вещь и повторное фото без перезагрузки страницы.

Статус: реализовано в коде, требуется живой Chrome test.

### Проверка B — приватность и экономика

В обычном Instant Preview отсутствует наш upload endpoint и платный inference API. Изображения пользователя не должны уходить на сервер LayerPorter.

Статус: статически защищено verifier-ом; живой Network test ещё требуется.

### Проверка C — регрессия сайта

`npm run build`, существующие smoke/verify/uniqueness проверки и новый LP-098 verifier должны проходить вместе. `/convert/`, существующие инструменты и production analytics не меняют поведение.

Статус: diff изолирован. GitHub Actions сейчас не запускает runner: PR #242 и независимый PR #239 завершаются до выполнения шагов с `steps=[]`, `runner_id=0`. Поэтому build нельзя считать ни пройденным, ни упавшим из-за LP-098. Production merge запрещён до реального build gate.
