Дата: 2026-09-10. Статус: готовы к передаче; это задания, не отчёт о выполнении кода.
Документы в ветке docs/strategy-audit-execution-2026-09-10. Код сайта брать из актуального master, MCP — из указанной ниже ветки.
Основание: [аудит](AUDIT-STRATEGY-2026-09-10.md), [roadmap](LAYERPORTER-ROADMAP.md), [#153](https://github.com/OlegStrateg/layerporter-site/issues/153).

## Разделение работы

Здесь решены: ближайшая воронка, порядок выпуска, границы SEO/инструмента/workspace, использование локалей, фокус MCP и отложенные продуктовые гипотезы.

Исполнитель по подписке делает: актуальную сверку кода, ограниченные правки, тесты, визуальную/файловую проверку, локализацию по готовым источникам, коммит и доказательства. Не запускает повторный стратегический аудит для каждой страницы.

Назад на стратегическое решение возвращать только факты, меняющие ставку: нет подходящего runtime/лицензии, основной результат технически недостижим, спрос относится к другой функции, стоимость/качество AI неприемлемы, новый серьёзный риск. Не приносить на согласование названия переменных, отступы и обычные решения внутри scope.

## Общая инструкция — включать в каждое задание

> Работай в существующем репозитории проекта, соблюдай его AGENTS. Сначала прочитай только относящиеся к задаче актуальные документы, issue и последние комментарии/PR: код могли уже поправить. Не перезаписывай чужую работу, используй отдельную ветку для нового изменения. Не повторяй общий аудит и не создавай новую семантическую базу, если источник уже есть. Выполни один указанный результат; после его DoD остановись. Дай commit/diff, реальные проверки и остаточные ограничения. Store click не называй установкой, CI/deploy success не называй live verified. Не публикуй/мерджи/деплой без разрешения, уже действующего в твоём чате.

**База:** OlegStrateg/layerporter-site@feat/LP-095-artifact-url-ingestion.
**Зависимость:** нет зависимости от S1–S6.

Устрани несоответствие README/distribution реальным URL tools; воспроизведи source-setup без sync core и гонку общего byte budget, исправь подтверждённое. Затем npm pack, установка tarball в чистую среду, реальный stdio-клиент: optimize → resource_link → resources/read → файл с совпадающими SHA-256/bytes/MIME/размерами. Проверь batch/variants, REJECT и ошибки временных ресурсов. Сохрани архитектуру MCP Resources. Не добавляй расширение, hosted transport, browser crawling и deploy-agent. Дай фактический release verdict, короткую инструкцию установки и список реально проверенных клиентов.

**Готово:** пользователь по инструкции получает открываемое оптимизированное изображение; документация описывает реальное поведение. Подача в каталоги после этого, не вместо smoke.

## S1 — конвертеры: закрыть ближайший пробел существующей воронки

**Куда:** текущий чат сайта, продолжение [#181](https://github.com/OlegStrateg/layerporter-site/issues/181).
**Рекомендация:** сначала проверить уже выпущенные RU/EN маршруты и заполнить один реальный пробел. Следующий кандидат локализации — RU WebP→JPG, если он ещё не реализован и сохранённая семантика по-прежнему поддерживает выбор.

> Прочитай свежие комментарии #181 и актуальный converter layout, mapping интентов и аналитику. PT-BR 9/9, RU JPG→PDF и RU PNG→PSD уже сообщены как deployed — не делай их заново. Выполни live smoke RU PNG→PSD: прозрачный PNG → скачанный PSD с одним слоем и сохранённой прозрачностью; отрази фактический результат. Проверь EN JPG→PDF на обнаруженное расхождение description «no file-count limit» с лимитом 40; если осталось, исправь текст по реальному engine. Дальше выбери только один отсутствующий exact URL по сохранённым данным, рекомендуемый кандидат RU WebP→JPG. Переиспользуй LocalizedExactConverterLayout, текущий runtime и готовые SEO-источники; основной инструмент выше SEO-текста. Не переделывай PT-BR или Home. Сохрани post-success CTA только для подтверждённого сценария расширения; NO EXTENSION допустим. Проверь локальные hub links, self-canonical, обратные hreflang и sitemap для новой страницы, события и пользовательский файл. Если кандидат уже сделан — сообщи доказательство и возьми следующий подтверждённый незакрытый exact route из того же issue, без повторной разработки.

**Готово:** один недостающий маршрут либо один воспроизведённый дефект доведён до проверенного результата; учтены актуальные сделанные шаги. Не ждать всей RU-сетки или полного аудита.

**Доказательства:** валидный выходной файл, desktop и реальный mobile viewport, отсутствие ложных обещаний, путь до правильного CWS и событие, HTTP/canonical/sitemap. Файл, которого нет в scope, не блокирует выпуск своей страницы.

## S2 — Extract Audio: веб-версия из готовой базы

**Куда:** чат сайта; [#183](https://github.com/OlegStrateg/layerporter-site/issues/183).
**Источники кода:** OlegStrateg/extract-audio-from-video и актуальный сайт.

> Найди существующий extraction runtime и поддержку форматов; используй его, не переписывай медиадвижок. По сохранённой семантике выбери один канонический URL без конфликта с существующими. Реализуй загрузку локального видео → извлечение звука → скачивание в одном действительно поддержанном формате; второй формат только если уже почти бесплатен по готовому коду. Отобрази реальные лимиты, состояние работы и понятные ошибки «нет аудиодорожки/формат не поддержан». Загрузка тяжёлого runtime по необходимости. После скачивания медиа в Pinterest предложи ссылку на этот веб-инструмент: V1 допускает выбор скачанного файла вручную. Не добавляй полный видеоредактор и бесшовный extension handoff. Используй существующую аналитику для load/success/download/source. Проверь файл со звуком, без звука, неподдерживаемый файл и mobile memory на ограниченном примере.

**Готово:** пользователь получает воспроизводимый аудиофайл; есть путь из Pinterest; точные ограничения показаны до ошибки.

## S3 — Crop + Resize: один небольшой общий рабочий сценарий

**Зависимость:** завершён текущий приоритетный срез сайта; не ждать универсальной AI-платформы.

> Сверь ADR-001-SEO-TOOLS-WORKSPACE.md и существующий runtime. Сделай минимальный общий документ/сессию для импортированного изображения, обрезки и изменения размера. SEO-входы узкие и статические, workspace после импорта без SEO-простыни. Пользователь переключает Crop/Resize без повторной загрузки файла. Не меняй SEO-URL на каждый внутренний режим, не создавай отдельный редактор для каждой страницы. Включи preview и экспорт, сохранение пропорций, явно согласованное поведение прозрачности/формата. Не делай слои, совместную работу, AI и обширный plugin framework. Переиспользуй текущий UI-shell; runtime загружай только при необходимости.

**Готово:** изображение импортировано → обрезано → изменён размер → скачано; реальные пиксельные размеры совпали; desktop/mobile удобны. Следующий инструмент использует ту же сессию.

## S4 — Compress, затем Text/Meme

**Зависимость:** рабочая сессия S3; доступное проверенное ядро оптимизации. Это две последовательные правки, не большой объединённый релиз.

> Сначала подключи подходящую часть проверенного image-core к веб-сжатию. Установи где обработка реально выполняется: Node/Sharp-код нельзя объявить браузерным или просто положить в browser bundle. Используй существующий доступный путь выполнения; если нужен новый платный backend, верни конкретный архитектурный вопрос и оценку вместо скрытой зависимости. Покажи исходный/выходной размер и скачивание; не обещай уменьшение веса для каждого файла. Проверь формат, прозрачность и размеры. После закрытия Compress отдельным шагом добавь текст поверх изображения и простейший meme-сценарий в ту же сессию. Не строй каталог тысяч шаблонов и генерацию AI-мемов в V1.

**Готово:** каждый из двух шагов заканчивается самостоятельным корректным экспортом. Если Compress упирается в новый серверный проект, не блокировать готовую клиентскую Text/Meme-функцию.

## S5 — продолжать локали партиями по существующей базе

**Зависимость:** проверен выбранный exact-инструмент. Уже выпущенные PT-BR/RU не переводить заново.

> Продолжай #181 по свежему статусу. Выбери следующий один exact URL/рынок на основании сохранённых GSC/Wordstat/Semrush/ASO, укажи источник и период. Не выдавай ASO score за частотность и не складывай пересекающиеся запросы в искусственный total demand. Переиспользуй готовый локализованный layout, с естественным Title/H1/кратким текстом и реальными лимитами. Проверь функцию, язык, navigation, canonical/hreflang/sitemap. Не запускай массовую генерацию 52 локалей. После успешного пилота можно следующую небольшую партию с тем же quality gate.

**Готово:** одна полезная локализованная страница корректно доступна и проверена; источник выбора записан. Появление в индексе/рост трафика измеряются позже, не обещаются по факту deploy.

## S6 — техническая индексация: только подтверждённые дефекты

**Куда:** продолжение [#156](https://github.com/OlegStrateg/layerporter-site/issues/156), приоритеты из более свежего #153.

> Проверь первый HTTP hop www/non-www для главной, exact tool и одной локали; canonical, параметры и отсутствие цепочек. В предыдущем браузерном наблюдении www оставался доступным, но штраф или потеря индексации не доказаны. Исправь только подтверждённое расхождение выбранного canonical host. Сверь live sitemap и build output: 200, канонические индексируемые URL, без fallback/битых локалей. На страницах текущей партии проверь self-canonical и взаимные hreflang. Отчёт indexed/not indexed из Search Console отделяй от Search Analytics. Безопасный узкий фикс не должен ждать полного #154; массовая миграция URL требует отдельной карты последствий.

**Готово:** таблица URL → исходный status/Location → конечный URL → canonical и конкретный diff, если дефект был. Не менять корректные URL только ради «чистоты».

## После MCP smoke: публикационный пакет, без нового продукта

> Подготовь из фактической выпущенной версии одно согласованное описание, рабочую установку, before/after пример, ограничения URL mode, артефактов/хранения, поддержку и совместимость. Сверь публичную доступность product/docs URL; package identity и Registry identity. Определи какие каталоги принимают текущий stdio/proprietary формат, не предполагай доступность приватного исходника. Внешние публикации выполняй только при разрешении владельца в этом чате. Результат — несколько работающих целевых размещений с проверенными install links; количество ссылок и выдуманные trust scores не цель.

## Что пока не отдаём в реализацию

Reader, платные фотосессии/мудборды, Canva layer reconstruction и дорисовку скрытого фона сначала проверяем как отдельные гипотезы. Для них нужны фактические функции текущих расширений, узкий запрос/аудитория, benchmark качества и цена результата. CRO/heatmaps не включаем в эту очередь.

- Что НЕ проверено, конкретный блокер, если есть.
- Следующий разблокированный шаг; без списка бесконечной полировки.
