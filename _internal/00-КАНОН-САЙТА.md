# LayerPorter — канон проекта сайта

Статус: рабочий источник правил для сайта.
Дата фиксации: 2026-08-29.

## 1. Канонический репозиторий

Код сайта LayerPorter ведётся в одном репозитории: `OlegStrateg/layerporter-site`.

Запрещено:
- создавать второй репозиторий сайта без отдельного архитектурного решения;
- вести параллельные версии сайта вне Git;
- менять боевой код без ветки, проверки diff и точки восстановления;
- считать локальные копии источником истины.

Git — источник истины кода, решений и истории.

## 2. Миссия сайта

LayerPorter — не набор случайных конвертеров. Это общая инфраструктура обработки и переноса визуального контента.

Базовый принцип:
РАСШИРЕНИЯ ЗАХВАТЫВАЮТ КОНТЕНТ → ОБЩЕЕ ЯДРО LAYERPORTER ЕГО ОБРАБАТЫВАЕТ.

Существующие направления:
1. Picture Converter.
2. Pinterest Downloader.
3. Сайт с локальными конвертерами.
4. Будущее общее ядро редактора.
5. В дальнейшем — перенос сайтов/элементов в редактируемые слои для PSD, Figma и Canva.

## 3. Бизнес-фильтр

Любая задача должна влиять минимум на одну величину:
1. органический или рекламный трафик;
2. конверсия;
3. удержание / повторное использование;
4. скорость и стоимость дальнейшей разработки.

Если эффект не измерим — задача получает низкий приоритет.

## 4. Архитектурные правила

- Не переписывать рабочий сайт без доказанного выигрыша.
- Сохранять Astro как основу, пока данные не доказывают необходимость смены.
- Сохранять локальную обработку файлов как ключевой продуктовый принцип.
- Тяжёлые библиотеки и модели не должны попадать в основной путь загрузки сайта.
- Один общий редактор; SEO-страницы только открывают нужный режим.
- Переиспользование общего ядра выше локальных реализаций.
- Перед собственной реализацией нетривиальной функции — обязательный поиск зрелых готовых решений.

## 5. SEO и поиск с ИИ

Официальные документы поисковых систем используются для:
- технических требований;
- правил и запретов;
- API;
- crawl/indexing;
- известных ограничений.

Они не считаются полным описанием реальных алгоритмов ранжирования и выбора источников ИИ.

Для значимых решений обязательны:
- фактическая выдача;
- собственные данные;
- GSC / Яндекс Вебмастер;
- GA4 / Метрика / Вебвизор;
- реальные кейсы и независимые эксперименты;
- Reddit, профильные форумы;
- GitHub Issues / Discussions / repositories;
- конкурентный разбор.

Каждая гипотеза:
HYPOTHESIS → EVIDENCE → COUNTER-EVIDENCE → RISK → COST → EXPECTED UPSIDE → TEST → METRIC → DECISION.

## 6. Стек, подтверждённый текущим репозиторием

- Astro 7.
- статическая генерация;
- Cloudflare Pages;
- Pages Functions;
- KV для части обратной связи/аналитики;
- локальные browser-side конвертеры;
- Web Workers;
- smoke-проверки;
- sitemap, robots.txt, canonical;
- llms.txt;
- security headers/CSP.

## 7. Правило изменений

Перед существенным изменением:
1. проверить ветку и status;
2. сохранить точку восстановления;
3. одна задача — одна ветка или один логический commit;
4. проверить diff;
5. выполнить автоматические проверки;
6. выполнить пользовательский сценарий;
7. только затем PR/merge;
8. production — только после проверки preview.

## 8. Главный запрет

Нельзя одновременно превращать LayerPorter в Canva, Photoshop, Figma, OCR-платформу, генератор всего и облачное хранилище.

Правильная модель:
ОДНО СИЛЬНОЕ ОБЩЕЕ ЯДРО → МНОГО ПРОДУКТОВ И ПОИСКОВЫХ ТОЧЕК ВХОДА.
