# LayerPorter — протокол проверок

## Проверка 1. Бизнес

Для задачи фиксируются:
- цель;
- ожидаемый эффект;
- метрика;
- стоимость;
- риск;
- переиспользование;
- критерий отмены.

Не принимать задачу без связи хотя бы с одной:
трафик / конверсия / удержание / скорость разработки.

## Проверка 2. Поиск и данные

Для SEO/AI Search:
- реальная SERP;
- собственные данные;
- GSC/Bing/Yandex;
- аналитика;
- конкурентные страницы;
- минимум одно независимое практическое свидетельство для нетривиальной гипотезы;
- контраргументы;
- confidence.

Форумный совет без проверки маркируется как НЕПРОВЕРЕННАЯ ГИПОТЕЗА.

## Проверка 3. UX

Проверять:
- пользователь понимает действие;
- путь завершается;
- mobile/desktop;
- loading;
- empty;
- error;
- retry;
- keyboard/focus;
- отсутствие потери данных;
- отсутствие неожиданного сброса состояния.

## Проверка 4. Техника

Перед merge:
- npm install/lock consistency;
- npm run build;
- smoke;
- console;
- network;
- HTTP status;
- canonical;
- sitemap/robots при затронутых маршрутах;
- security headers;
- производительность затронутой страницы;
- отсутствие тяжёлой зависимости в основном bundle без необходимости.

## Проверка 5. Git

Перед началом:
- правильная ветка;
- чистая/понятная рабочая область;
- baseline commit;
- одна логическая задача.

Перед сдачей:
- git diff;
- тесты;
- commit;
- PR;
- preview;
- rollback path.

## Open Source First

Перед любой нетривиальной реализацией проверить:
- GitHub repositories/topics/code search;
- issues;
- discussions;
- pull requests;
- forks;
- releases;
- npm;
- Stack Overflow;
- Reddit/форумы.

Проверять:
- активность;
- license;
- security;
- browser support;
- bundle size;
- performance;
- critical issues;
- возможность замены.

Перед собственной реализацией письменно ответить:
"Почему готовые решения не подходят?"

Без убедительного ответа собственное ядро не писать.
