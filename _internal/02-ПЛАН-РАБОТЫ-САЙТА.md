# LayerPorter — план работы по сайту

Статус: стартовый план после первичного аудита 2026-08-29.

## Текущее состояние

Подтверждено:
- сайт работает на Astro 7;
- деплой построен вокруг Cloudflare Pages;
- есть Pages Functions;
- есть 9 инструментов/чекеров в текущей публичной структуре;
- есть статические SEO-страницы, guides/formats;
- есть sitemap, robots, canonical, JSON-LD на части страниц;
- есть llms.txt;
- есть security headers;
- есть smoke-скрипты;
- есть аналитический код и продуктовые API;
- репозиторий активно используется и содержит свежие изменения.

Вывод:
переписывание сайта сейчас не обосновано.

# Этап 0. Базовый аудит и измеримость — P0

## Цель
Получить реальную картину: что уже работает, что даёт трафик/конверсию, что тормозит рост.

## Работы
1. Карта всех URL и index/noindex intent.
2. Проверка sitemap, robots, canonical, redirects, 404.
3. Проверка JSON-LD по типам страниц.
4. Проверка Core Web Vitals и сетевого профиля.
5. Проверка аналитики и качества событий.
6. Подключение/проверка GSC, Bing Webmaster, Яндекс Вебмастер.
7. Проверка Bing AI Performance.
8. Снятие baseline по AI citations/mentions.
9. Проверка текущих landing/welcome/uninstall воронок.
10. Конкурентная выдача по основным коммерческим кластерам.

## Результат
Не список "ошибок", а ранжированный backlog по влиянию.

# Этап 3. SEO-архитектура существующих инструментов — P1

1. Разобрать реальный спрос.
2. Сопоставить каждый URL с одним главным интентом.
3. Найти каннибализацию.
4. Найти "почти победившие" запросы.
5. Усилить страницы, которые уже имеют сигнал.
6. Только затем создавать новые страницы.

Принцип:
REFRESH / CONSOLIDATE / KEEP раньше, чем массовое CREATE.
